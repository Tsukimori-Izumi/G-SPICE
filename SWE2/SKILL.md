# 目的
定義されたソフトウェア要件（REQ）を論理的なコンポーネントに分解し、それぞれの責任範囲（機能）、コンポーネント間の相互作用（インターフェース）、および階層構造を定義することで、システムの整合性と保守性を確保すること。

# インプット
- ソフトウェア要件仕様書 (SRS): `c:\AntiGravity\Gantt\SWE_report\SWE1\01_SRS.md`
- 報告書テンプレート: `c:\AntiGravity\Gantt\SWE_agent\SWE2\TEMPLATE.md`

# 手順
1. **コンポーネント分割**: 全ての REQ をカバーするように、システムを独立性の高い機能単位（モジュール、クラス等）に分割します。
2. **静的構造設計**: 各コンポーネントの責任（役割）と、システム全体における物理的・論理的な配置を定義します。
3. **動的構造設計（インターフェース）**: コンポーネント間のデータ受け渡し、関数呼び出し、および依存関係を定義します。
4. **追跡性の確保**: 各コンポーネントがどの **REQ-xxx** を充足するためのものかを「上位追跡性」として紐付けます。
5. **アーキテクチャ設計書の出力**: テンプレートに従い、`c:\AntiGravity\Gantt\SWE_report\SWE2\02_SoftwareArchitectureDesign.md` を出力します。

# アウトプット
- ソフトウェアアーキテクチャ設計書: `c:\AntiGravity\Gantt\SWE_report\SWE2\02_SoftwareArchitectureDesign.md`

# 制約事項
- 出力はすべて日本語で行うこと。
- 各コンポーネントには **COMP-xxx**（例: COMP-001）形式の一意なIDを付与すること。
- モジュール間の不必要な結合を避け、凝集度の高いアーキテクチャを目指すこと。
- **必ず指定された TEMPLATE.md の構造を維持すること。**
