# 目的
完成したソフトウェアが、顧客および設計側で合意した全ての要件（REQ）を完全に満たしていることを、エンドユーザーの視点で客観的に検証・証明すること。

# インプット
- ソフトウェア要件仕様書 (SRS): `c:\AntiGravity\Gantt\SWE_report\SWE1\01_SRS.md`
- 最終成果物（ソースコード/ブラウザ画面）: `c:\AntiGravity\Gantt\main.py`
- 報告書テンプレート: `c:\AntiGravity\Gantt\SWE_agent\SWE6\TEMPLATE.md`

# 手順
1. **適格性確認テスト設計**: 全ての原子要求（REQ）に対し、その要求が達成されたとみなせる「合格判定基準」を具体的なテストケースへと変換します。
2. **システム検証の実施**: 開発環境から独立した視点で（または自動化されたE2Eテストを通じて）、実際の動作が要件と一致するかを確認します。
3. **要求適合性の判定**: 各テスト結果に基づき、対応する要求が「充足」されているかを Yes/No で厳格に評価します。
4. **追跡性の付与**: 各テストケースがどの **REQ-xxx** の充足性を証明するものかを一対一で対応付けます。
5. **検証報告書の出力**: テンプレートに従い、`c:\AntiGravity\Gantt\SWE_report\SWE6\06_SoftwareQualificationTestReport.md` を出力します。

# アウトプット
- ソフトウェア適格性確認テスト報告書: `c:\AntiGravity\Gantt\SWE_report\SWE6\06_SoftwareQualificationTestReport.md`

# 制約事項
- 出力はすべて日本語で行うこと。
- 各テストケースには **QT-xxx**（例: QT-001）形式の一意なIDを付与すること。
- 要件に対する網羅性を最優先とし、一つでも不適合があれば「不合格」と判定し SUP9（問題管理）へ通知すること。
- **必ず指定された TEMPLATE.md の構造を維持すること。**
